## Caveats / deferred items

**Item 24 — duplicate-email danger banner.**
The schema validates email format, but the "this email already
exists" detection requires a backend lookup that the API doesn't
currently expose as a debounced uniqueness endpoint. The duplicate
case still surfaces — the API returns a conflict error which
becomes a `toast.error` — but the inline danger banner with a
"View employee →" deep link is not yet there. Unblock path: add
`GET /api/employees/exists?email=<…>` and wire a debounced lookup
in the sheet's email field.

**Item 27 — salary-change-requires-reason.**
The salary warning banner appears in edit mode the moment
`salaryPkr` becomes dirty (commit 8d9228f). The actual "reason"
field is a separate UX surface the spec describes but the existing
`employeeCreateSchema` / `employeeUpdateSchema` doesn't carry a
reason column on the update endpoint — historical reason capture
goes through the dedicated `change-salary` dialog instead
(`ChangeSalaryDialog`, surfaced from the profile actions menu).
The sheet currently relies on this existing flow for audit-grade
reason capture; the warning banner sets the user's expectations
and a follow-up should either (a) bring reason capture into the
sheet by extending the update endpoint, or (b) keep the
`ChangeSalaryDialog` as the canonical path and remove the salary
field from the sheet entirely. **Defer the decision** to a
product call.

**'Save as draft' button.**
Spec mentions this behind a future feature flag — not implemented;
the footer ships Cancel + Save only. Recorded in the commit
message; no DECISIONS.md entry yet because it's a UI affordance
not a system-level architectural choice.
