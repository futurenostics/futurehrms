## Escape-hatch usage

Two intentional `eslint-disable-next-line fn-tokens/no-default-utilities`
comments, both documented inline:

1. **`<LogIn>` glyph in the form-side hero tile** (`login-card.tsx` ~L381):
   `text-white`. The glyph sits on an indigo→violet accent gradient that
   is dark in both themes — `text-fn-fg-invert` would flip to dark in
   dark mode and disappear against the gradient. The brand mark
   stays white in both themes by design.

2. **`<span>F</span>` in the orbit-center logo tile** (`login-card.tsx`
   ~L539): same rationale as above.

Both have inline justification comments. No other escapes used.

## Findings

### Finding 1 — Outer card radius mapped 2xl → fn-xl

- **Section:** `LoginCard` outer wrapper
- **Divergence:** Source had `rounded-2xl` (16px). The fn-radius scale
  has 14px (lg) and 18px (xl) but no 16px.
- **Resolution:** Mapped to `rounded-fn-xl` (18px). 2px wider than the
  pre-Reset value, but inside the design's intended visual
  language for large card surfaces. The catalog (extracted-tokens.md
  §3, OPEN-4) already documented this snap: keep 14/18 distinct,
  fold one-off 16 into 18.
- **Tradeoff:** If the design source explicitly wanted 16, the
  reviewer should flag and we add a `--fn-radius-lg-plus` (16) token.
  For now the visual difference is sub-perceptual.

### Finding 2 — Spacing-scale fractional-key naming gotcha

- **Section:** PromoPanel, all positioning utilities
- **Divergence:** During the perl-driven bulk token swap, the regex
  greedily matched `left-1/2` and `top-1/2` (Tailwind's fractional
  positioning utilities for 50%) as if they were spacing tokens,
  producing broken `left-fn-1/2` class names.
- **Resolution:** Second perl pass reverted those back to their
  Tailwind keyword form. The ESLint rule's bans only cover numeric
  scale values (per the rule's design), so `left-1/2` is correctly
  not banned — the issue was an over-greedy migration script.
- **Followup:** Documented in the commit message so the next
  Sub-phase D screen migration uses a tighter regex.
